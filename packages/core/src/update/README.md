# 在线更新与镜像

在 WebUI「设置 → 关于 → 软件更新 → 更新来源」中选择：

- **自动切换**：先尝试 GitHub，下载失败后按候选列表顺序切换。
- **GitHub 直连**：只访问 GitHub。
- **指定镜像**：更新包只从指定镜像下载；版本和校验值查询仍会尝试 GitHub。

内置 10 个候选镜像：`ghfast.top`、`ghproxy.net`、`gh-proxy.com`、`github.chenc.dev`、`fastgit.cc`、`gh.noki.icu`、`cors.isteed.cc`、`gh-proxy.org`、`githubproxy.gohj99.site`、`github.xxlab.tech`。

「检测可用性」从 SnowLuma 所在服务器请求当前版本更新包的前几个字节，检查 ZIP/Gzip 文件特征，并按可用性和响应延迟排序。它会取消剩余响应体，避免检测时下载完整文件。检测延迟不代表下载速度；镜像可用性也会随网络环境变化。

可以选用检测通过的来源、仅保留可用镜像，或编辑候选列表（每行一个，最多 16 个）。地址是追加完整 GitHub URL 的 HTTP(S) 代理前缀，可包含路径，不能包含账号、密码、查询参数或片段。修改后点击「保存来源」，下次检查和下载生效。设置保存在 `config/runtime.json` 的 `updateSource` 字段中，不影响正在下载的任务。

GitHub API 返回 403、超时或不可用时，更新器读取已有的正式版发布页面获取版本，从已有附件列表读取对应文件的 SHA-256。无需额外发布 metadata 文件，也支持已发布的发行包。页面格式变化或缺少校验值时会报错，不会跳过校验。

所有更新包都须通过 SHA-256 校验后才能解包。API 提供的精确大小会继续校验；网页回退时使用响应的 Content-Length，缺少该头时限制最大下载量为 256 MiB 并验证完整摘要。下载中断或校验失败后，自动模式会清理该次下载的临时文件，再尝试下一个来源。解包仍检查目录边界、版本和目标平台。

更新先暂存，下次重启时替换运行文件，配置、日志和消息数据保留。源码运行和容器部署不启用文件替换；容器应更新镜像。
