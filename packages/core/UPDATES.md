# 版本切换与在线更新

发行包的 WebUI 可从版本列表选择当前平台有可用安装包的版本，包括正式版、预发布版、同版本重装和降级。降级必须明确确认：旧版本可能无法读取新版本写入的配置或数据库，切换前应自行备份数据。源码开发模式不支持在线替换程序。

版本列表来自发行源。仅有 tag、缺少当前平台安装包、缺少有效发行清单或校验信息的版本不能安装；网络和发行源错误会显示给用户。切换仍经过下载校验、暂存和重启后文件事务，不在正在运行的服务中逐文件覆盖。替换失败时保留原有恢复流程。

## 启动与权限

在线更新需要发行包的父启动器运行。通常执行 `launcher.sh`、`launcher.bat` 或发行包的 `index.mjs` 即可：入口启动父进程，由父进程在旧服务退出后应用更新并启动新服务。单独设置 `SNOWLUMA_UPDATE_ROOT` 不能替代父启动器的 IPC 连接。

服务初始化和开始下载前会检查程序目录与发行清单内条目的读写权限，并实际创建、重命名、删除临时探测文件。只读文件系统、不可读文件、不可写的程序子目录和符号链接目标会给出具体错误。更新器不会自行提权、更改目录所有者、修改 Docker 安全设置或操作宿主机。

更新只替换清单中的程序、WebUI 和 native 文件，不替换 Node，也不改写配置、消息数据库或 QQ 登录数据。Node 的路径和 file capabilities 因而保留；若所选版本要求更新的 Node、系统库或 QQ，应先升级对应运行环境。

## Docker 部署

Docker 与普通发行包使用相同的版本切换流程，前提是程序目录可写且父启动器可用。官方 [Docker Framework](https://github.com/SnowLuma/SnowLuma.Docker.Framework) 的 Supervisor 使用 `/usr/local/bin/node /app/runtime/index.mjs`，可保留发行包的父启动器；其启动脚本不会在每次启动时重新解压覆盖 `/app/runtime`。

不同镜像和历史版本的目录所有者可能不同。例如镜像构建时的 runtime UID 与启动时 `SNOWLUMA_UID` 不一致，就会导致程序目录不可写。WebUI 会显示实际权限错误；需要管理员按容器内实际运行 UID/GID 修正程序目录权限，或使用适当配置的可写 runtime 卷。修改 Node 的所有者或替换 Node 可能清除其 capabilities，应单独核对；在线切换不会替管理员处理这些部署权限。

容器内切换修改的是该容器的程序文件：

- SnowLuma 服务重启后，新版本继续运行。
- 原容器停止再启动，通常保留容器可写层；具体仍取决于镜像自己的入口脚本。
- 删除并重建容器时，未持久化的 runtime 会丢失，新容器重新使用镜像内版本。
- 容器镜像的名称、tag、QQ、Node 与系统依赖均不会随在线切换改变。更新这些组件仍需更新镜像。

若需要在重建容器后保留所选版本，可为实际程序目录增加持久卷。以下仅展示需要追加的配置，应同时保留原有的数据卷、安全选项、端口等配置：

```yaml
services:
  snowluma:
    volumes:
      - snowluma-runtime:/app/runtime

volumes:
  snowluma-runtime:
```

挂载整个程序目录，避免仅挂载单个程序文件或 `native` 子目录妨碍文件事务的重命名与替换。首次初始化、卷内文件权限和备份由部署方负责。保留的 runtime 卷也会覆盖后续镜像自带的程序目录；升级镜像不会自动刷新这个卷中的程序版本。若镜像使用其他程序目录，应挂载其实际目录。

QQ 中已注入的 Hook 与磁盘上的 native 文件是两份不同生命周期的代码。服务重启会断开并重建连接，但已运行的 QQ 进程可能继续使用先前加载的 Hook。所选发行版必须兼容镜像中的 QQ、Node 和系统库；涉及 Hook 版本变化时，可能还需要重启 QQ 或原容器后再验证连接。在线更新不能证明任意旧版与现有 QQ 兼容。

## 后端接口

- `GET /api/update/releases?page=1`：分页查询版本，`force=true` 强制刷新当前页；页码范围为 1 到 100。
- `POST /api/update/download`：提交 `{ "version": "1.2.3" }` 开始暂存；降级需同时提交 `"allowDowngrade": true`，该字段只接受布尔值。
- `POST /api/update/restart`：仅在暂存完成后接受请求；HTTP 响应完成后退出旧服务，由父启动器应用更新。

版本号使用规范 SemVer，GitHub tag 的 `v` 前缀由发行源边界处理。下载与应用只接受通过既有平台、归档和发行清单校验的程序包。
